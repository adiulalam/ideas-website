# Template and front-end rules

## Escaping
- `<?= e($value) ?>` for every dynamic value, in text **and** in attributes.
  Always quote attributes with double quotes.
- Raw output is allowed only for:
  - `$sanitizer->render($idea['IdeaText'])` (HTMLPurifier-cleaned idea text)
  - `$view->partial(...)` and `$csrf->field()` (HTML generated by our own code)
  - integers cast with `(int)`
- Image `src` values go through `Images::src()` **and** `e()`.
- URLs built from data: `Url::to()` for query strings, then `e()`.
- Never echo `$_GET`, `$_POST`, `$_SERVER['PHP_SELF']` or `REQUEST_URI` directly.

## Forms
- Every `method="post"` form includes `<?= $csrf->field() ?>`.
- Destructive forms add `data-confirm="Question?"`. `app.js` shows the dialog.
- Re-display user input after validation errors with `e()`. Never re-display passwords.

## JavaScript and CSS
- No inline `<script>`, no `on*=` attributes, no `javascript:` URLs. The CSP
  (`script-src 'self'` + reCAPTCHA) blocks them. Add behaviour to
  `public/assets/app.js` with `data-*` attributes, as progressive enhancement:
  pages must still work without JS.
- Styling uses Tailwind v4 utilities and the component classes in
  `resources/css/app.css` (`btn`, `btn-primary`, `card`, `input`, `label`, ...).
  New classes only exist after `npm run build:css` / a Docker rebuild.
- Layout is responsive with Tailwind breakpoints (`sm:`, `md:`, `lg:`). There
  is no server-side mobile detection any more. Check pages at phone width.
- External images get `referrerpolicy="no-referrer"`. Decorative images use `alt=""`.
